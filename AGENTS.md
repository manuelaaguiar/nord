# NÓRD public demonstration

The current deployment is an intentionally public, browser-local interactive demonstration. Only generic examples belong in HTML, scripts, seeds or source exports. Visitors may create their own journey in this browser only, using a separate local namespace. Do not introduce real travel details, source documents, personal journal content, private links or credentials.

The existing D1 and R2 bindings are retained to preserve earlier private data. Do not delete, reset, backfill or seed production data. The public Worker denies all data APIs and mutations before any private handler runs. Browser navigations (`GET`/`HEAD` with `Accept: text/html`) to unknown non-API paths receive a branded pt-BR 404; APIs and other requests still receive 403 JSON. It rejects anonymous callers, spoofed identity headers and platform service callers alike. There is no verified owner identity binding in the app. Do not infer owner privilege from an email/header or lack of identity.

Do not remove this deny boundary or reopen editing/AI until an explicit authentication and authorization design is approved and tested. Changing Sites audience alone does not create app authorization. Existing private API implementations are retained for recovery/future work but inaccessible in public mode. Their unit tests use isolated synthetic SQLite data.

Keep the same `.openai/hosting.json` project, D1 and R2 bindings. No migrations are part of demonstration publication. Preserve append-only historical revisions, stable operation IDs, optimistic version checks and local recovery code. Do not expose a previous private deployment while the Site is public; restore private policy before any rollback.

Public UI: `data/dashboard-html.ts`, `public/nord/visitor.js`, `local-travel.js`, `global.css`, `typography.css`, `planner.js`, `market.js`, `globe.js`, `global-content.js`. Only fixed, public exchange-rate reads to the documented allowlisted sources may leave the browser, without credentials or trip/profile data. No uploads or paid AI. Only explicit visitor-local records use `nord.visitor-trip.v1.personal`, a distinct example key, and the mode preference. Never read or clear legacy private-app keys. Local storage is not account isolation; warn about shared devices, clearing data, private browsing, no synchronization and no automatic backup. Preserve memory on storage failure, provide a downloadable copy, and serialize local commits with Web Locks. Missing Web Locks fails saving visibly rather than risking cross-tab overwrite. Fonts are local OFL assets; Apple system fonts are referenced only, never distributed. Keep the original Luna artwork and brand.

Run `npm test`, `npm run typecheck`, `npm run lint`, the Sites build helper, `npm run check:secrets`, and the public-bundle privacy scan before publication. Test both generated and custom Site domains anonymously. A private version must be deployed and verified fail-closed before changing audience. No access change, credential creation or hosting migration is implicit in a visual edit.

Global planning revision: the profile interview generates deterministic suggestions explicitly identified as such, never simulated AI or reservations. Validate local updates on a cloned candidate before mutating live state. Import only validated JSON and preserve prior raw records in append-only local recovery copies before replacement; keep the same personal/example namespaces and old data.
